# 项目执行

这是流程型 skill。执行阶段复用规划入口，不创建执行入口。任务入口是唯一状态面板；`T-*` 只作为已确认实现契约，不维护执行状态或执行记录。开发阶段的目标只有一个：按照技术方案正确且完整地实现，不多、不少、不偏离。复杂功能测试、E2E、前端验证和完整回归放到开发后的集中测试/验收阶段。

## 触发与边界

**触发**：用户要求执行已确认任务计划、继续开发、按 `project-planning` 任务实现、处理执行阶段阻塞，或验收缺陷明确回退到执行阶段时使用。

**不触发**：任务入口未确认时返回 `project-planning`；实现过程中发现方案需要改变时返回 `project-design`；发现需求语义需要改变时返回 `project-requirements`；用户要求集中测试、验收或发布时交给对应阶段 skill。

**与其他 skill 的关系**：本 skill 可调用 `project-review`，见其 SKILL.md。审查不可用或未通过时，入口不得写入 `execution_status: confirmed`。

## 存储与路径契约

入口旁复用同名目录：

```text
<任务入口同名目录>/
├── tasks/T-*.md
├── evidence/EVD-*.md
├── logs/LOG-*.md
├── research/RT-*.md
└── review/REV-*.md
```

原始命令输出、日志和审查报告放支撑材料；入口只写摘要、状态和证据链接。任务文件不写执行记录，不新增 `execution_status` frontmatter。

执行只允许写这些规划文档位置：

- 入口 frontmatter：`execution_status`、`execution_review`。
- 入口任务表：当前 `T-*` 的执行状态。
- 入口风险、审查或执行摘要中与真实执行结果相关的状态摘要。
- 支撑材料：`EVD-*`、`LOG-*`、`RT-*`、`REV-*`。

不得改写入口的覆盖、任务名称、完整实现结果、依赖和已确认风险；不得改写任务文件契约。凡会改变用户确认过的范围、接口、验收定义、实现边界或测试阶段交接，必须回到责任阶段。

## 阶段与流转

入口 `execution_status` 使用：

| 状态 | 含义 | 可进入的下一状态 |
|---|---|---|
| `pending` | 尚未开始执行 | `executing` / `blocked` |
| `executing` | 正在执行或等待审查确认 | `confirmed` / `blocked` / `pending` |
| `confirmed` | 开发实现已审查且经用户确认，可进入后续测试/验收阶段 | `executing` |
| `blocked` | 缺少继续执行的必要条件 | `executing` |

入口任务表每行执行状态只使用 `pending` / `in_progress` / `done` / `not_verified` / `blocked`。这些状态只写在入口表格，不写入任务文件。

开始执行时把入口 `execution_status` 改为 `executing`。

## 入口门槛

只接受同时满足以下条件的任务入口：

- `status: confirmed`，且 `plan_review` 已通过。
- `execution_status` 为 `pending` 或 `executing`；或验收入口有开放 `DEF-*` 指向本入口、责任阶段为执行，允许按“缺陷回退”重开。
- 任务表每行链接一个真实、自含的 `tasks/T-*.md`，任务文件不维护状态。
- 没有未解决阻塞、未解释偏差或会推翻规划契约的发现。

门槛不满足时，记录发现并返回对应责任阶段。

## 执行步骤

1. 读取任务入口，确认范围、开发检查、任务顺序、依赖、风险和当前入口状态。默认选择入口顺序中第一个依赖已完成、可执行且入口表格状态不是 `done` 的任务。
2. 读取当前 `T-*` 及其直接链接的方案、调研或证据；不要一次加载全部任务细节。
3. 执行前核对当前任务的 `F/D/C/V` 追踪、文件、接口、实施步骤、最小检查、代码审查要点和测试阶段交接。任务不自含、路径不存在且未标明新增、接口契约矛盾或要求重新设计时，返回 `project-planning` 修订。
4. 将入口任务表中当前任务状态改为 `in_progress`。
5. 按任务实施步骤完成真实接入。不得用 mock 自有模块、stub、fallback、固定返回、样例数据、临时内存存储或空校验替代计划行为；mock 只限任务明确允许的外部边界。
6. 运行任务声明的最小检查：格式、lint、typecheck、编译或最基础测试。只运行能证明基础质量的必要命令；不为开发阶段新增持久化测试文件，不执行复杂功能测试、E2E、浏览器检查、前端交互验证或完整回归。
7. 如需临时脚本或临时测试帮助定位局部逻辑，执行后删除，不把它作为任务产物、证据或后续约束。
8. 直接审查代码是否与技术方案和任务契约一致：逐项检查真实文件、调用链、字段、状态、错误处理、持久化、UI 接入和禁止捷径。审查发现偏离时修正实现；需要改变契约时返回责任阶段。
9. 任务实现完成且最小检查通过、代码审查未发现偏离时，在入口任务表写 `done`。实现完成但最小检查因外部环境、权限、账号、数据或服务无法运行时写 `not_verified` 并说明恢复条件。当前无法继续写 `blocked`。

## 失败与偏差

- 最小检查失败时，在入口摘要或 `LOG-*` 记录命令、关键错误、根因判断、修复和重试结果；仍在修复时保持 `in_progress`。
- 同一问题连续三轮仍无法推进且缺少可自行解决的条件时，把入口任务表写 `blocked`，入口 `execution_status` 可写 `blocked`，并说明恢复条件。
- 只有实现已完成、检查本身因外部条件无法运行时才能标记 `not_verified`。格式、类型、构建或基础测试因本任务代码失败，不得改写为 `not_verified`。
- 文件、命令、接口、步骤、审查要点或范围与项目不符时，返回规划阶段；影响需求、架构、数据、兼容、安全或用户体验时，返回相应责任阶段；执行者不得静默偏离。
- 事实不明但不改变任务契约时，登记 `RT-*` 并调用 `project-research`。

## 缺陷回退

验收入口的开放 `DEF-*` 明确责任阶段为执行，且修复不改变已确认规划契约时：

1. 核对缺陷、复现证据、影响任务和验收入口的双向链接。
2. 把入口 `execution_status` 从 `confirmed` 改为 `executing`，把 `execution_review` 重置为 `pending`；只在入口任务表把受影响任务回退为 `in_progress`，未受影响任务保持原状态。
3. 按原规划契约修复，并重新执行受影响任务的最小检查和代码审查；复杂复现、功能回归、E2E、前端验证仍交给后续测试/验收阶段。
4. 重新通过独立执行审查和用户确认后，才能再次写入 `execution_status: confirmed`；原审查和原确认不得复用。

修复需要改变规划分区、任务边界、接口契约或测试阶段交接时，停止执行并返回 `project-planning` 重新进入 `discussing`、修订、审查和确认。

## 整体完成

所有任务在入口任务表为 `done` 后，做一次开发阶段收尾：

1. 运行入口声明的基础检查集合，不扩大到复杂功能测试、E2E、浏览器检查、前端交互验证或完整回归。
2. 检查代码差异是否只覆盖已确认任务范围。
3. 对照技术方案和全部 `T-*` 审查实现完整性：真实路径、接口、数据、状态、错误处理、持久化、UI 接入、依赖顺序和禁止捷径。
4. 调用 `project-review` 审查入口、任务契约和代码差异。审查报告写入同名目录 `review/REV-*`，入口 `execution_review` 链接该报告；审查不通过时回退入口任务表相关状态并继续执行。

只有以下条件全部成立，才请求用户确认开发结果：

- 入口任务表所有任务为 `done`，没有 `not_verified`、`blocked` 或未解释偏差。
- 最小基础检查通过，或无法运行的外部条件已明确且不掩盖实现错误。
- 代码审查确认实现与技术方案和任务契约一致，没有额外范围或模拟实现。
- 独立执行审查通过。

用户确认后把入口 `execution_status` 改为 `confirmed`，交给后续集中测试/验收阶段；未满足时保持 `executing`。

## 提问契约

能从任务、代码、方案、日志或调研获得的信息自行处理。只有缺少用户才能提供的访问条件或决策，并且错误假设会改变范围、方案、数据、安全、兼容或用户体验时才提问。问题一次只问一个，给出推荐处理和选择影响，放在回复最后的 `## 需要你确认` 区块，后面不追加内容。

## 边界声明

本 skill **不做**：

- 不创建执行入口或在任务文件写执行记录。
- 不改写已确认需求、方案和规划契约。
- 不把开发阶段变成集中功能测试阶段；不强制 E2E、浏览器检查、前端交互验证或完整回归。
- 不持久化临时测试文件。
- 不自动提交、推送、部署或操作生产环境，除非用户明确要求。
- 不伪造、覆盖或压缩失败事实。
