# 项目调研

流程型 skill。只调查一个边界明确的问题，把证据交还调用阶段。`completed` 与 `blocked` 是本仓库既有调研结果字段值，必须生成报告并双向链接。

## 触发与边界

**触发**：阶段入口中已有 `RT-*`，或入口 `RT-*` 链接到 `research/RT-*`，且任务要求调查项目事实、外部资料、来源冲突或能力限制。

**不触发**：用户只是泛泛要求"帮我看看"但没有 `RT-*`；需要修改需求、方案、任务、执行状态或验收结论；需要创建独立调研入口。

**与其他 skill 的关系**：`project-knowledge` 可用时按它的读取、查询和写入规则检索或沉淀项目知识；不可用时跳过并记录能力限制。外部网页核实时优先调用浏览器/Playwright 类能力；不可用时记录不可用能力和影响范围。

## 存储与路径契约

- 调研材料放在调用入口旁同名目录的 `research/RT-编号-简短英文-slug.md`。
- 入口已链接 `research/RT-*` 时更新同一文件，不为同一 `RT-*` 另建报告。
- 缺少标题或 slug 来源时使用保守名，例如 `research/RT-001-incomplete-task.md`。
- 复用或增量更新已有材料时保留原路径并补齐与入口 `RT-*` 的双向链接。
- 报告正文结构使用本 skill 自带模板 [assets/research-report.md](assets/research-report.md)；模板是格式参考，真实报告不得保留尖括号占位符。

## 阶段与流转

| 状态 | 含义 | 可进入的下一状态 |
|---|---|---|
| `pending` | 入口已登记但尚未形成报告 | `completed` / `blocked` |
| `completed` | 完成条件满足，关键结论均有证据，入口已回写 | 无 |
| `blocked` | 输入缺失、范围变化、访问条件缺失或证据不足以完成 | `pending`（调用阶段补齐条件后重试） |

流转条件：

- `pending` -> `completed`：调研任务完整、完成条件逐项满足、报告与入口双向链接、入口结果回写为 `completed`。
- `pending` -> `blocked`：任务缺少必需字段、范围实质变化、缺少用户才能提供的访问条件，或关键来源不可访问且无可替代证据。
- `blocked` -> `pending`：调用阶段补齐恢复条件并显式要求重试。

## 执行步骤

1. 读取阶段入口、当前 `RT-*`、已链接材料和与问题直接相关的已有材料；若入口只保留任务链接和结果链接，沿链接读取 `research/RT-*`。
2. 校验 `RT-*` 是否包含单一可回答的问题、范围与不调查内容、所需证据、完成条件、受影响入口条目和真实路径。缺任一项时仍创建或更新标准路径报告，写 `blocked`，列出缺失字段、已检查入口和恢复条件，并把入口结果回写为 `blocked`。
3. 开始新调查前按顺序复用材料：先查 `project-knowledge`（可用时），再查当前入口旁 `research/` 中完整适用或部分适用的报告；完整适用的报告可直接复用，部分适用的报告在原路径增量更新。
4. 按完成条件确定要检查的项目位置和外部来源。项目事实优先检查真实代码、配置、测试、提交历史和运行结果；外部事实可能变化时必须在线核实官方文档、源码或一手资料。
5. 逐项核对证据，区分来源陈述、项目事实和 Agent 推断；每个关键结论必须能追溯到具体来源。来源冲突时并列记录冲突、适用范围和取舍依据。
6. 在报告中记录实际使用能力、不可用能力和影响范围，例如项目文件、命令结果、浏览器/Playwright、官方文档、`project-knowledge`、联网能力。
7. 只在 `completed` 前处理知识库沉淀：可复用结论在 `project-knowledge` 可用时归档或更新；一次性结论、不可用或失败分别写 `skipped` / `error` 和原因。`blocked` 报告不沉淀。
8. 把报告或复用材料链接回入口 `RT-*`，并按"写回边界"只更新允许字段。

知识库沉淀记录必须放在报告末尾，包含三个字段：`复用价值`（可复用 / 一次性）、`沉淀状态`（done / skipped / error；done 时附 `project-knowledge` 返回路径）、`错误`（错误摘要或无）。

## 校验与门槛

判定 `completed` 前必须满足：

- [ ] 完成条件逐项满足。
- [ ] 关键结论均有具体来源或项目证据。
- [ ] 事实、来源陈述和 Agent 推断已区分。
- [ ] 冲突、限制和能力缺口已说明。
- [ ] 调研材料与入口 `RT-*` 双向链接。
- [ ] 入口 `RT-*` 已写入 `completed`。
- [ ] 知识库沉淀已按能力处理并记录结果。

判定 `blocked` 前必须满足：

- [ ] 已生成或更新报告。
- [ ] 已列出已检查位置和来源、不可用能力、缺失条件、当前能确认与不能确认的内容、恢复条件。
- [ ] 入口 `RT-*` 已写入 `blocked`。
- [ ] 报告记录知识库沉淀为 `skipped`，原因是未形成可沉淀结论。

## 失败与回退

- 输入字段缺失：不继续猜测任务，按标准路径写 `blocked` 报告并回写入口。
- 范围实质变化：不把新范围混入旧报告，写 `blocked` 交还调用阶段决定是否新建或改写 `RT-*`。
- 外部来源不可访问：不得根据搜索摘要包装成已确认事实；记录不可用来源、替代来源尝试和影响范围。
- 已确认结论需要撤销：更新同一报告，保留原结论、撤销原因、新证据和影响范围，并把入口结果改为与当前报告一致的 `completed` 或 `blocked`。

## 提问契约

默认不重新访谈用户。只有缺少用户才能提供的访问条件或事实，并且缺失会阻止完成时才提问。问题放在回复最后的 `## 需要你确认` 区块，只包含一个问题、推荐处理和不同选择的影响。

## 证据与完成定义

外部事实可能变化时必须在线核实；搜索结果页和摘要只能用于发现来源，不能作为结论证据。不能访问的来源必须记录为能力限制，不得伪装成已确认事实。

## 边界声明

本 skill **不做**：

- 不创建独立调研入口。
- 不替调用阶段修改需求、方案、任务、执行状态、验收结论或吸收状态。
- 不用无来源推断、搜索摘要或来源数量冒充可靠结论。
- 不用 mock、固定返回或未验证实现冒充完成。
- 不沉淀 `blocked` 报告中的未完成结论。

### 写回边界

只允许修改当前 `RT-*` 的回写字段：简洁链接格式只更新 `调研结果` 为 `completed` 或 `blocked`；内联任务格式只更新 `调研报告` 和 `执行结果`。同一 `research/RT-*` 文件中可更新报告正文、来源、能力记录、知识库沉淀和执行结果。

禁止修改用户故事、功能点、验收要求、技术决策、任务内容、执行状态、验收结论或吸收状态。
