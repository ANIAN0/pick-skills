# 项目需求

这是流程型 skill。目标是先维护项目根目录的 `ROADMAP.md`，再围绕一个里程碑形成给人阅读的需求草稿，并在确认前清理为正式正文。需求正文的唯一目的，是让读者用最短时间理解“为什么要做、给谁做、要做到什么、怎么判断做对”；凡是不服务这个目的的内容，都不得进入正文。涉及 UI 时只在正文相关功能下写必要 UI 要求。不要进入技术方案、任务或实现阶段。

## 触发与边界

**触发**：用户要求做需求调研、梳理需求、维护项目路线图、拆出里程碑、确认用户故事/功能点/验收要求，或需要为技术方案阶段提供已确认需求时使用。

**不触发**：用户已经要求技术设计、任务规划、实现、验收或故障排查时，交给对应阶段 skill；用户只要求调研事实且已有 `RT-*` 时，调用 `project-research`，见其 SKILL.md。

**与其他 skill 的关系**：本 skill 可调用 `project-research`，见其 SKILL.md；可调用 `project-review`，见其 SKILL.md。二者不可用时，必须记录未审查或未调研的影响，需求不得标记为 `confirmed`。

## 存储与路径契约

- 项目路线图固定为项目根目录 `ROADMAP.md`。
- 路线图格式固定为一行一个里程碑：`- [<status>] M-001：<一句话核心内容>`。
- 里程碑编号使用 `M-*` 递增；`status` 只使用 `discussing` / `confirmed` / `in_progress` / `done` / `blocked`。
- 冒号后的核心内容只能是一句话，不写子弹列表、说明段、负责人、日期或验收细节。
- 需求入口只在 `workplace/<版本>/requirements/` 下创建或更新一份文档；`discussing` 时它是可读草稿，`confirmed` 后它是正式正文。优先使用用户给出的路径，其次复用同一里程碑已有入口，否则按 `YYYY-MM-DD-功能名.md` 命名。
- 讨论期间只维护这一份需求草稿，不为了同步流程信息额外维护 `meta.md`、`logs.md` 或 `todo.md`。确有未确认问题时，只允许在草稿文末临时追加 `## 待确认`；进入 `confirmed` 前必须删除该节或把结论合并回对应正文位置。
- 支撑材料放在入口旁的同名目录中，按需创建，不预建空目录或空文件；只存放调研、证据汇总、必要决策依据和审查报告。

## 阶段与流转

| 状态 | 含义 | 可进入的下一状态 |
|---|---|---|
| `discussing` | 里程碑或需求仍在澄清 | `confirmed` / `blocked` |
| `confirmed` | 需求正文已完成定稿清理、审查且经用户确认，可进入技术方案 | `discussing` |
| `blocked` | 缺少继续调研或确认的必要条件 | `discussing` |

切换条件：

- `discussing` -> `confirmed`：路线图里程碑、需求正文、必要支撑材料、定稿清理、独立审查和用户确认全部完成。
- `discussing` -> `blocked`：缺少用户或外部系统才能提供的必要条件，且无法安全假设。
- `confirmed` -> `discussing`：下游证明已确认需求需要改变，或路线图里程碑核心内容发生实质变化。
- `blocked` -> `discussing`：用户或项目文件补齐恢复条件。

## 执行步骤

1. 确认项目根目录并读取 `ROADMAP.md`；不存在时创建最小路线图，首个里程碑从用户当前目标或项目文档中提炼为一句话。
2. 选择当前里程碑：优先使用用户指定的 `M-*`，其次复用与请求匹配的现有里程碑，否则新增下一个 `M-*`；一次需求调研只围绕一个里程碑。
3. 校准路线图：发现里程碑过大、重复或核心内容变化时，先更新 `ROADMAP.md`，保持每个节点一句话；不能把需求细节写进路线图。
4. 确认入口路径：只在 `workplace/<版本>/requirements/` 下创建或更新与当前里程碑对应的一份需求入口。输出完整路径并说明“如需修改请告知，否则继续”，然后继续执行。
5. 读取上下文：查看相关项目文档、代码、页面、接口、数据、配置、glossary、`CONTEXT.md`、ADR、相似功能和当前里程碑上下游节点。能查到的事实自己查，不问用户。
6. 写入或更新可读草稿：新建时使用 [需求入口模板](assets/requirements-entry.md)。先确定目标读者和一条从上到下的阅读路径，再按这条路径组织背景、用户、场景和功能；每个功能点在同一小节内写清能力、规则、异常和验收要求。草稿从第一版起就按正文质量写，不写聊天记录、过程日志或原始素材堆。
7. 讨论缺口：只问会改变里程碑核心内容、需求范围、用户故事、功能点、验收要求或 UI 需求的问题。相关问题一次成组提问，通常 2-5 个；每组都给推荐答案和影响。未确认问题只在草稿文末临时 `## 待确认` 中保留，不创建单独待办文件。
8. 按需创建支撑材料：只有真实需要调研、证据汇总、必要决策依据或审查报告时，才在同名支撑目录中创建对应文件。正文保留最终结论；支撑材料只用于溯源，不承担讨论期同步账本职责。
9. 定稿清理：进入确认前，不重新生成一篇正文，只对当前草稿做机械清理：删除或合并 `## 待确认`，删除过程性话语，消除重复表达，检查清理前后没有语义漂移或已确认内容丢失。
10. 自检、独立审查、用户确认：定稿清理自检通过后调用 `project-review`。审查通过后请用户确认里程碑、核心正文和 UI 需求（如有），全部确认后把对应路线图节点改为 `confirmed`。

## 校验与门槛

进入下一步或判定完成前必须满足：

- [ ] `ROADMAP.md` 位于项目根目录，每个 `M-*` 只有一句核心内容，且状态值来自统一集合。
- [ ] 当前需求正文明确关联且只关联一个 `M-*`，入口路径真实，位于 `workplace/`，且一个里程碑当前只有一份需求正文。
- [ ] 正文开头能让读者在不读支撑材料的情况下理解本需求的目标、用户和结果；后续章节按理解顺序展开，不按流程产物、讨论顺序或模板栏目堆叠。
- [ ] 正文顶部没有 front matter 或字段表；正式正文中没有文档编号、负责人、状态、审查、变更记录、讨论过程、待确认问题、待定决策或任务清单。
- [ ] 正文没有独立的“本期边界”“验收要求”“待定决策”“变更记录”章节；功能点和验收要求在同一功能小节内一一对应。
- [ ] `confirmed` 前已完成定稿清理：文末不存在 `## 待确认`，没有过程性话语，清理前后没有语义漂移或已确认内容丢失。
- [ ] 用户故事、功能点、验收要求完整、简洁、互相对应，并直接服务当前里程碑；同一信息只出现在最能讲清它的位置，不在多个章节重复。
- [ ] 涉及 UI 时，必要 UI 要求写在相关功能小节中；不生成 `ui/UI-*`、`prototype/PROTOTYPE-*` 或其他 UI 产物文件。
- [ ] 必要调研已完成并回写，支撑材料与正文双向链接；没有为状态、日志或待办额外创建同步文件。
- [ ] 独立审查通过，用户明确确认里程碑和需求内容。

审查后修改时，必须比较上一轮正文与本轮正文：若核心里程碑、用户故事、功能点、验收要求或 UI 需求少了已确认内容且没有明确撤销依据，视为退步，不得进入 `confirmed`。

## 失败与回退

- `discussing` 下发现请求跨多个里程碑：先拆分或让用户选择当前里程碑；未选定前不创建多个需求入口。
- `discussing` 下缺少必要事实：在草稿文末 `## 待确认` 登记 `RT-*` 并调用 `project-research`；调研结论未回写或为 `blocked` 时，不得确认需求。
- `confirmed` 后下游证明需求需要改变：对应路线图节点改回 `discussing`，需求正文重新作为可读草稿维护，并在本次回复中说明哪些后续方案、计划、执行或验收确认失效。
- 独立审查不可用或未通过：保持 `discussing`，记录原因和下一步修复条件。

## 提问契约

满足全部条件才问用户：

- 答案会实质改变路线图里程碑、需求结论或本期范围。
- 无法从项目、已有文档、历史对话或调研获得答案。
- 错误假设会导致明显返工、范围错误、用户可见问题或风险。

提问时放在回复最后的 `## 需要你确认`，后面不再追加总结。能安全假设时，直接写明假设、依据和影响并继续推进。

## 下沉材料

按需读取 [需求细则](references/requirements-rules.md)：

- 需要创建支撑材料、调研项、证据汇总或需求决策依据时。
- 需求中等以上复杂，涉及跨模块、权限、持久化、异步、兼容、迁移、AI/Agent 或三条以上用户路径时。
- 需要判断用户故事、功能点、验收要求是否写到位时。
- 下游回退导致已确认需求需要重开时。

## 边界声明

本 skill **不做**：

- 不设计架构、数据库、API 或代码修改方案。
- 不把路线图写成项目计划、甘特图、任务清单或版本日志。
- 不把支撑材料、过程记录、变更日志、待确认问题或待定决策留在正式正文。
- 不创建 UI 需求文件、原型文件或 UI 设计产物。
- 不生成 `prototype/PROTOTYPE-*`。
- 不自动替用户确认需求完成。
