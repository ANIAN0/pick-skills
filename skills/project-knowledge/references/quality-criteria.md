# 项目知识库质量标准

只在迁移、健康检查或大范围更新后读取。

## OKF 基础层

| 维度 | 合格标准 |
|---|---|
| OKF 最低契约 | 每个普通概念有可解析 frontmatter 和非空 `type` |
| 保留文件 | `index.md` 和 `log.md` 可缺失；存在时按 OKF 语义使用，不当作普通概念 |
| 宽容入口 | 根 `index.md` 没有 `okf_version` 时只提示 warning，不判定 bundle 不兼容 |
| 链接 | 使用标准 Markdown 链接；断链只作为 warning，不能拒绝消费 |
| 宽容消费 | 未知 `type` 和扩展字段被保留，不因无法识别而删除 |

## 项目 profile 层

| 维度 | 合格标准 |
|---|---|
| 本 skill 字段契约 | 每个普通概念有非空 `type`、`title` 和 `description`；`Project Code` 概念有非空 `source_path` |
| 入口 | 根 `index.md` 声明 `okf_version: "0.1"` 并链接 `quickstart.md` 和所有已有分类 |
| 快速开始 | `quickstart.md` 是 `Project Overview` 概念，面向人和 coding agent 说明项目知识版图、主要分类和阅读建议 |
| 渐进导航 | 每个已有分类的 `index.md` 列出实际概念和一句话描述 |
| 文档站导航 | 根入口、quickstart 和分类索引能让新读者进入主要分类或关键概念 |
| 日志 | `log.md` 按日期倒序记录有意义的知识变化 |

## 内容质量

| 维度 | 合格标准 |
|---|---|
| 证据 | 关键结论可追溯到代码、测试、阶段文档、报告或外部来源 |
| 持久价值 | 内容能支持后续判断，不是临时任务状态或过程副本 |
| 单一概念 | 同一结论维护在稳定路径，不因不同阶段重复创建 |
| 准确性 | 关键内容与当前项目和原始证据一致 |
| 边界 | 说明结论适用条件、限制或失效条件 |
| 关联 | 链接周围文字解释关系，强关联按需建立反向链接 |

## 文档站检查

- 根 `index.md` 是否能作为 OKF 渐进导航入口，而不是只列文件。
- `quickstart.md` 是否像 OpenWiki 入口一样解释项目是什么、知识区怎么分布、不同读者从哪里进入。
- 分类入口是否说明该分类解决什么问题、适合什么读者进入。
- 关键概念是否能从入口通过一到两次点击发现。
- 是否存在只有标题、source map 或少量空话的薄页面；有则合并到更宽概念、quickstart 或索引。
- `viz.html` 如已生成，是否只是 `project-kb/` 的派生视图；不要手工维护与源 Markdown 冲突的内容。

## 分类检查

- `domain/` 是否保存业务和领域知识，而不是代码实现细节。
- `architecture/` 是否表达跨模块结构和契约，而不是逐文件复述。
- `code/` 的 `source_path` 是否与真实源码相对路径一致。
- `decisions/` 是否只记录重要且不能从当前事实直接推导的选择。
- `workflows/` 是否覆盖参与概念、顺序、关键分支、失败和验证。
- `operations/` 是否记录可复用的运行、配置、发布、故障处理知识，而不是临时操作日志。
- `integrations/` 是否说明外部系统、协议、认证边界和失败条件。
- `testing/` 是否能指导修改后的验证选择，而不是复制测试文件清单。

## 代码概念检查

- 能否据此理解文件承担的可验证能力。
- 是否记录容易被破坏的规则、边界和兼容约束。
- 强关联文件是否说明原因并在必要时反向链接。
- 是否能选择相关测试和修改后验证。
- 源码删除或重命名后，条目和引用是否同步处理。

## 过程文档沉淀检查

- 是否只提取长期结论，没有复制完整入口、调研或审查报告。
- 是否链接原始来源，并在可修改时由来源链接回来。
- 同一结论是否先搜索并更新已有概念。
- 来源与当前项目冲突时是否暂停写入，而不是选择方便的版本。

## 处理顺序

1. 修复会导致错误读取的格式、断链和错误路径。
2. 修复与当前项目冲突的事实。
3. 合并重复概念并更新索引。
4. 补充当前工作需要的证据、边界和测试映射。
5. 不为提高表面覆盖率批量创建低价值条目。
