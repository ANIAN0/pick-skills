# 项目 Wiki profile

建设、刷新、查询或审计项目说明时读取。本 profile 以 OKF 为规范层，项目站点是发布视图。

## 受众与信息架构

先为用户、集成方、开发者或运维人员列出任务和所需事实。公开页只投影目标读者需要的信息；内部拓扑、源码证据、未发布能力、凭据和安全细节留在 OKF/证据层。

按实际需要使用 `overview/`、`quickstart/`、`guides/`、`concepts/`、`reference/`、`operations/`、`faq/`、`changelog/`；内部库可增加 `architecture/`、`workflows/`、`decisions/`、`testing/`、`code/`。导航顺序是“是什么 → 首次成功 → 常见任务 → 精确参考 → 运维与版本”，不镜像菜单或源码目录。

已有站点中尚未进入 OKF 的事实页是导入来源；已能从 OKF 重建的页面是发布视图。保留视图的 URL、导航、版本路由和生成器并记录投影映射，身份、来源和生命周期仍以 OKF 为准。

## 页面差量

- `Quickstart`：可执行步骤、预期结果、失败入口、下一步。
- `Guide`：目标、前置条件、步骤、验证、回退/故障处理。
- `Reference`：字段/参数、约束、默认值、错误、兼容性、示例。
- `Concept`：机制与边界，链接相关 guide/reference。
- `Changelog`：版本、日期、用户变化、破坏性变更、迁移。

架构和工作流从可观察触发点说明组件协作、数据/状态、输出、失败和恢复，再链接实现证据。一个事实只有一个权威概念页；导航摘要说明页面解决的问题。

## 事实与发布验收

API/协议以发布 schema、路由、模型、契约测试和实际响应为准；CLI/配置以当前帮助、解析代码、默认配置和运行结果为准；UI 以当前界面、接口行为和验收结果为准；版本能力以发布记录和验证结果为准。设计稿、未来需求和旧文档只说明计划或历史。

发布视图必须满足：新读者两次导航内找到首次成功路径和主要 reference；示例与当前版本一致；默认值、鉴权、错误码和版本无冲突；无秘密或未发布能力；现有构建、链接、导航和代码块渲染通过。
