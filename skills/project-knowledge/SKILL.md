# 知识库与 Wiki

这是知识型 skill。把知识库作为**回答系统**维护：结构由读者问题、权威来源和知识生命周期决定，而不是由现有文件夹或素材格式决定。

## 触发与边界

**触发**：用户要求设计、初始化、迁移、读取、查询、写入、维护或审计本地知识库/Wiki；把已验证且可复用的结论归档为长期知识；从产品知识中检索背景并生成需求上下文包或候选需求草稿。

**不触发**：用户只要求总结单份材料且没有知识库意图；用户要修改知识库外的研发路线图、需求阶段入口或确认状态；或请求目标完全属于“边界声明”列出的事项。

知识库中的 `requirements/`、需求状态和需求关系是对既有项目材料的**知识投影**，由本 skill 自主建设和维护。存在 PRD、REQ、需求索引或能力映射不构成调用任何需求流程 skill 的理由；只有用户另行要求修改知识库外的正式研发流程时才结束本 skill 边界并处理新任务。

## 存储与路径契约

- 已有知识库沿用用户指定或现有入口可定位的根目录、导航文件、生成器和发布路径；不建立与既有导航竞争的第二套入口。
- 新建文件型知识库的根目录由用户目标或已有项目结构确定。根目录至少承担读者入口、Agent 维护说明、schema 和变更记录四项职责，具体文件契约见 [通用知识契约](references/knowledge-contract.md)。
- 初始化、重建、迁移或批量刷新时，在 `<kb-root>/_meta/coverage.json` 维护文件级来源清单和处置状态；格式、完成等式与独立审查要求见 [覆盖与审查契约](references/coverage-and-review.md)。
- 个人知识库按 [个人知识库 profile](references/personal-profile.md) 命名项目、参考项目、主题、经验和来源；项目 Wiki 按 [项目 Wiki profile](references/project-wiki-profile.md) 延续站点路径；产品 Wiki 按 [产品 Wiki profile](references/product-wiki-profile.md) 使用稳定需求 ID 和关系路径。
- 现有内部项目知识库默认位于 `<项目根>/project-kb/`；该路径的兼容命令见 [本地工具](references/tooling.md)。
- 同一稳定概念只保留一个规范路径；移动前更新入链、索引和替代关系，未知用户文件保持原位。

## 执行步骤

1. **定位并选择 profile**：读取现有入口、维护说明、schema、目录和生成配置；按主要读者与检索任务选择个人、项目 Wiki 或产品 Wiki profile。混合场景用一个主 profile 决定导航、发布边界和执行流程，次 profile 只扩展实际需要的内容类型与质量规则，不触发其他流程型 skill。根路径、profile 组合、发布边界和可修改范围均已确定后完成。
2. **定义检索契约**：从现有材料确认主要读者、3–7 个高频问题、权威来源及优先级、稳定内容类型、强关系和过期条件。每个高频问题都已映射到来源与内容类型后完成。
3. **建立全量来源账本**：先递归枚举项目范围内所有文件；生成目录、依赖缓存等只能按明确规则排除。全部文件至少完成分类；所有既有文档、需求、设计、测试、发布、排障和现有 Wiki 页面逐文件记录 `mapped / consolidated / superseded / duplicate / excluded / pending` 之一及目标页或理由。运行 [本地工具](references/tooling.md) 的 coverage inventory；完成等式成立且权威文档根目录没有 `pending` 后完成。
4. **建立事实基线**：在全量清单上选择需要纵向深读的材料；涉及真实项目时执行 [项目理解契约](references/project-understanding.md)，追踪关键业务旅程、运行链路、数据/状态和失败路径。源码必须全量发现和组件化分类，但只对高频问题、核心链路及高风险结论深读；既有文档语料不得用抽样代替逐文件处置。每个计划中的核心页面都有精确证据，且目录名、入口装配或单份需求摘要不再承担超出其证明力的结论后完成。
5. **建立控制面**：按通用知识契约创建或修复读者入口、Agent 维护说明、schema、来源登记、覆盖账本和日志；已有站点把这些职责映射到现有文件。每类知识的身份、字段、关系、来源和生命周期都有唯一权威定义后完成。
6. **迁移或写入**：保留原始资料并建立来源映射；按稳定身份搜索已有条目，语义合并后写入可复用结论，标记推断、冲突和未知；同步强关系、最近索引、覆盖账本和日志。本次写入满足存储与路径契约，且每条新知识可追溯、可发现后完成。
7. **读取与查询**：从维护说明和根入口进入，用 ID、标题、别名、description、tags 与正文召回候选页，沿替代、所属、依赖、能力和来源关系扩展，再用权威来源复核高风险或时效性事实。所有高相关候选与完整替代链均已处理，并能区分事实、推断、冲突和缺口后完成。
8. **生成产品需求上下文**：包含产品内容类型时执行其“新需求检索与候选草稿”步骤；先形成可追溯的需求上下文包，再按用户要求输出候选草稿。上下文包中的背景、约束、相关需求和来源都可回溯后完成。
9. **持续维护**：在来源变化、版本发布、新需求确认、项目完成、用户纠错或审计发现问题时，先同步来源账本，再更新稳定概念、关系、索引和日志；旧结论按生命周期保留替代入口。变更后的覆盖状态、入口、关系和状态一致，旧链接仍能引导到当前结论后完成。
10. **运行确定性验证**：执行 coverage 与严格本地链接检查，再执行适用的结构、内容、profile 和真实检索问题检查；现有 OKF/project-kb 可追加兼容工具检查。所有适用检查都产生真实结果，`pending`、断链和未执行项已记录后完成。
11. **执行独立审查**：初始化、重建、迁移或一次创建/重写 5 个以上正文页时，交给未参与建设的 subagent/reviewer，只提供项目根、Wiki 根、检索目标与原始文件，不提供建设者结论；按覆盖与审查契约核对漏项、来源、断链、薄页和真实检索。所有阻塞问题修复并复验后完成。

## 校验与门槛

判定完成前必须满足：

- [ ] [质量与验收](references/quality-criteria.md) 中适用于当前变更范围的结构、内容、维护、profile 和检索检查全部通过。
- [ ] 覆盖账本满足 `inventory_total = 六类处置项之和`，`pending = 0`；权威文档目录每个文件都有处置结果，目录级 `sources` 不能替代文件级记录。
- [ ] 初始化、迁移或批量刷新已通过事实基线门槛；项目 Wiki 的核心结论能回到完整业务/运行链路，而不只回到目录、入口文件或需求摘要。
- [ ] 每个检查结果都来自实际知识库、真实来源或真实检索问题；样例、mock 或只读到单页不能替代端到端验证。
- [ ] 需要独立审查的任务已有 fresh-context reviewer 证据；每轮记录 `pending`、断链、无来源结论、薄页和漏项数量，下一轮不得增加阻塞问题且至少减少一项，否则停止无效修订。
- [ ] 未执行项及其影响已记录；任何必要检查无法运行时不能标记为 `done`。

## 失败与回退

- 根路径、发布边界或知识身份无法从材料确认，且错误假设会造成错误写入：停止写入，只询问当前最关键的问题；读取和清单整理仍可继续。
- 文件清单不完整、覆盖等式不成立、权威文档仍有 `pending` 或只用目录级来源声称完整：停止批量写入，先补来源账本；不得用“已看过主要文件”代替。
- 项目理解门槛未通过：停止新增和批量改写内容页，只交付已检查范围、已确认事实、证据缺口和下一步调查路径；不得让用户代替 Agent 选择“应该补深哪个模块”，除非可访问材料已查尽且选择依赖用户独有的业务事实。
- 发现现有页面由目录扫描、入口文件或模板推断生成且与项目事实不符：先停止传播，将其降为 `draft`、标记待核验或撤回公开导航；按真实链路复核后再更新，不在错误页面上继续扩写。
- 权威来源冲突且无法判定当前事实：保留原始资料，把综合结论维持或降为 `draft` 并记录冲突；请求的确定结论无法继续时标记 `blocked`。
- 迁移或更新后校验失败：保留原始资料和已落盘变更，报告失败路径与影响；修复并重新验证前不删除旧文件、不把结果标记为 `done`。
- 构建器、依赖或关键来源不可用：完成可安全执行的部分，列出未验证范围，结果标记为 `not_verified`。
- 任务需要独立审查但 subagent/reviewer 不可用：执行一次对抗式复审并报告限制，但结果只能标记为 `not_verified`，不能 `done`。

## 证据与完成定义

- 建设、迁移或维护任务的 `done` 证据包括：实际知识库路径、全量来源账本及分类统计、事实基线、变更文件、严格链接检查、适用 profile 检查、真实检索验收和独立审查结果。项目 Wiki 的事实基线还必须包含已追踪的关键业务/运行链路及其证据。
- 查询或候选需求草稿任务的 `done` 证据包括：实际读取的知识页与原始来源、处理过的强关系或替代链、当前结论、冲突和缺口；草稿中的背景、范围与约束可逐项回溯。
- 审计任务的 `done` 证据包括：检查范围、通过项、问题路径、严重影响和未检查项。
- 写入完成但任何必要验证无法运行时使用 `not_verified`；缺少权威来源或存在无法裁决的冲突，导致请求目标当前无法继续时使用 `blocked`。

## 边界声明

本 skill **不做**：

- 不修改知识库外的正式项目路线图、需求阶段入口或用户确认状态；可以把这些来源完整投影为知识库需求页、状态和关系。
- 不管理远程知识服务、站点部署、CI 发布、跨库同步或自动传播。
- 不按源码或资料目录批量制造低价值页面，不把任务进度、临时讨论或完整过程材料复制进知识层。
- 公开内容按项目 Wiki profile 的发布边界处理，不把内部证据直接发布。
