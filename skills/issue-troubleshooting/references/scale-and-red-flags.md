# 修复规模与红灯信号

## 规模评估标准

对已确认的根因，按以下维度判断修复规模：

| 维度 | 小修 | 大修 |
|---|---|---|
| 涉及文件数 | 不超过 3 个文件 | 超过 3 个文件 |
| 涉及模块 | 单一模块 | 跨模块或跨层 |
| 预估工时 | 少于 4 小时 | 4 小时或更多 |
| 变更性质 | 逻辑修正、参数调整 | 架构调整、接口变更、新增组件 |
| 测试影响 | 修改少量测试 | 新增测试套件或重构测试结构 |
| 前后端 | 仅一端 | 前后端都需要改动 |

小修必须满足全部条件：不超过 3 个文件、不跨模块、预估少于 4 小时、不涉及接口变更。

大修满足任一条件即可成立：超过 3 个文件、跨模块或跨层、预估 4 小时或更多、涉及接口变更或架构调整、前后端都需改动、阶段 3 中已有 3 次或更多假设验证失败。

## 大修方案概要

大修进入计划前，先整理以下输入：

```markdown
## 修复方案概要

- 根因说明：
- 修复范围：
- 修复策略：
- 修复约束：
- 已有技术方案引用：
- 不走小修的原因：
```

如果项目中已有 `workplace/<version>/tech-design/`，只引用相关章节作为约束来源；没有已有技术方案时，不创建新的 tech-design 文档。

## 计划模块补充字段

大修计划中的每个修复模块应补充：

```markdown
**关联根因**：
**风险点**：
**回退方案**：
```

计划最后增加回归验证模块：

```markdown
### M{N}: 回归验证

**目标**：确认修复未引入新问题
**层**：跨层
**前置依赖**：所有修复模块

**子步骤**：
1. 运行全量测试套件
2. 验证原 bug 场景已修复
3. 检查关联功能的回归

**验收标准**：
- 全量测试 通过
- 原 bug 复现步骤不再触发
- 关联功能无回归
```

## 红灯信号

看到以下信号时，停止当前修复动作，回到对应阶段：

| 信号 | 处理 |
|---|---|
| "先快速修一下，回头再查" | 回到阶段 1，先找根因 |
| "改一下 X 试试看" | 回到阶段 3，写出单一假设并验证 |
| 多个改动一起提交 | 拆成单一修复，避免无法判断哪个改动有效 |
| 跳过测试，只手动验证 | 先补最小失败测试或一次性验证脚本 |
| 参考实现没读完 | 回到阶段 2，完整阅读参考实现 |
| 问题很简单、不需要流程 | 继续流程；简单问题也必须有根因 |
| 已失败 2 次还想再试一次 | 第 3 次失败后必须进入大修评估 |
| 每次修复都在不同位置暴露新问题 | 视为架构信号，进入大修评估 |
| 大修想直接动手 | 先产出修复方案概要并走计划 |
| 测试全通过但功能不对 | 回到阶段 1，优先排查降级逻辑 |
| 想加 catch 或 fallback 兜底 | 先解释为什么会有这个错误，不得掩盖根因 |

## 常见借口对照

这些说法通常是跳过流程的信号，不是合理例外：

| 借口 | 现实 | 正确动作 |
|---|---|---|
| 问题很简单，不需要流程 | 简单问题也有根因；跳过流程会把症状当根因 | 走阶段 1，至少确认错误、复现和近期变更 |
| 情况紧急，没时间调查 | 紧急时猜测更容易扩大损失；证据收集可以很短，但不能为零 | 做最小诊断，定位故障层，再决定止血动作 |
| 先试这个，没用再查 | 第一次修改会污染证据，后续更难判断 | 先写出假设和验证方式 |
| 我先加个 retry/catch/fallback 止血 | 这类改动可能掩盖真实错误，让问题变隐形 | 先证明失败是瞬态、可恢复或用户可接受的降级 |
| 测试之后再补 | 没有失败测试，无法证明修复覆盖根因 | 先补最小失败用例或一次性验证脚本 |
| 多改几处更快 | 无法隔离哪个改动有效，还会引入新问题 | 一次只改一个变量 |
| 参考实现太长，按经验改 | 未理解模式就改，容易破坏隐含约束 | 完整读参照并列差异 |
| 已经花了很久，不能推倒重来 | 沉没成本不是证据；继续叠加会更难收敛 | 删除无效尝试，带着新证据回到阶段 1 或阶段 2 |
| 资深同事说就是这里 | 权威意见是线索，不是验证 | 把它写成假设，用最小证据验证 |
| 再试最后一次 | 2 次失败后继续试通常是架构信号 | 第 3 次失败后进入大修评估 |

## 用户纠偏信号

当用户说出以下提示时，按对应方式处理：

| 用户提示 | 含义 | 处理 |
|---|---|---|
| "是这样吗？" | 你可能做了未验证假设 | 回到阶段 3 验证 |
| "能不能看到……？" | 证据不足 | 回到阶段 1 收集证据 |
| "别猜了" | 你在无根因时提修复 | 停止修复建议 |
| "好好想想" | 需要质疑根本问题 | 回到阶段 2 或进入大修评估 |
| "是不是卡住了？" | 当前方法不奏效 | 明确阻塞点或换假设 |
