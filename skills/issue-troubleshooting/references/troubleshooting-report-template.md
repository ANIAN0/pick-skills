# 排查报告模板

修复完成后，把排查过程与结论记录到 `workplace/<version>/troubleshooting/YYYY-MM-DD-{问题关键词}-排查报告.md`。如果项目没有可判断的 `workplace/<version>/`，在最终回复中给出同样结构的报告内容。

```markdown
# {问题关键词} 排查报告

## 问题描述

- 现象：
- 复现步骤：
- 影响范围：

## 根因分析

- 根因：
- 证据链：
- 排除的假设：

## 修复内容

- 修复方式：
- 修改文件：
- 新增测试：

## 验证结果

- 测试执行：
- 回归检查：

## 经验教训（可选）

- 
```

## 填写要求

- 小修：完整填写所有章节。
- 大修：修复内容可以写"参见修复计划 {计划文件路径}"，验证结果必须在计划执行完成后补充。
- 问题描述必须包含可复现步骤，或说明为什么无法复现以及采用了哪些替代证据。
- 根因必须追溯到源头，不能只写中间表象。
- 修复内容必须对应根因，不能写成"尝试修改"。
- 验证结果必须包含命令、输出摘要或可复现行为；不能用 mock、stub、占位数据或样例输出伪装成真实验证。
