# UI 需求文档生成器

流程型 skill。把需求文档或前端代码转换为结构化 UI 需求文档，供 UI 设计师制作设计稿；输出是 Markdown 规格文档，不是技术规格或 HTML 原型。

## 触发与边界

**触发**：用户明确要求生成 UI 需求文档、给设计师的页面规格、前端需求文档、UI 设计文档；或用户提供 PRD、功能规格、业务需求、用户故事、前端页面/组件代码，希望提取页面布局、字段、交互和状态信息。

**不触发**：用户要生成可交互 HTML 原型时，调用 `html-prototype-generator`，见其 SKILL.md；用户要实现前端代码、修复 UI bug、做视觉设计稿或组件库规范时不使用本 skill。

**与其他 skill 的关系**：`html-prototype-generator` 可作为后续原型生成步骤，不是本 skill 完成 UI 需求文档的前提；不可用时本 skill 仍输出 Markdown 文档。

## 存储与路径契约

- 默认输出目录：`workplace/{版本号}/prototypes`；若项目已有明确文档目录或用户指定目录，优先使用该目录并在结果中说明。
- 单页文档命名：`ui-req-{页面名称}.md`。
- 多页汇总文档命名：`ui-req-all.md`。
- 页面名称用于文件名时去除路径分隔符；同名文件存在时追加短后缀或更新汇总文档中对应页面，不静默覆盖无关内容。

## 阶段与流转

| 状态 | 含义 | 可进入的下一状态 |
|---|---|---|
| `discussing` | 正在识别输入、抽取页面清单或等待页面清单确认 | `confirmed` / `blocked` |
| `confirmed` | 页面清单、范围和输出目录已确认或可由材料明确推出 | `in_progress` |
| `in_progress` | 正在逐页生成 UI 需求文档 | `done` / `not_verified` / `blocked` |
| `done` | 文档已生成且通过检查点 | 无 |
| `not_verified` | 文档已生成但无法完成必要检查 | 无 |
| `blocked` | 缺少无法替代的输入或访问条件 | `discussing` |

流转条件：

- `discussing` -> `confirmed`：页面清单、页面类型和输入来源已明确；若页面清单来自材料且低风险，可直接确认并说明依据。
- `confirmed` -> `in_progress`：输出目录和文档粒度已确定。
- `in_progress` -> `done`：执行检查点全部通过。
- 任意状态 -> `blocked`：输入不可读、页面范围无法从材料判断，且错误假设会实质改变文档内容。

## 执行步骤

1. 判断输入类型：需求文档输入包括 PRD、功能规格、业务需求、用户故事；前端代码输入包括 Vue/React/Angular 组件、页面模板和现有前端项目代码。
2. 读取输入材料并识别页面清单。需求文档中提取页面、功能、数据结构和业务规则；前端代码中提取组件结构、表单字段、事件处理、弹窗/抽屉和状态展示。
3. 输出页面清单表格，包含序号、页面名称、页面类型和功能概述。页面类型使用 `list`、`form`、`detail`、`dashboard`；无法归类时说明依据并使用最接近的类型。
4. 页面清单需要用户确认且不能从材料可靠推出时停在 `discussing`；材料足以判断时继续生成，并在最终说明确认依据。
5. 对每个页面生成 UI 需求文档：页面概述、页面布局、字段详情、交互行为、弹窗/抽屉、提示信息。文档结构见 [references/ui-doc-template.md](references/ui-doc-template.md)；多页面时同时生成汇总文档。
6. 根据需要补充设计建议，但只写与页面结构、视觉强调、按钮优先级或响应式适配相关的建议；不得写成实现方案或组件库绑定说明。
7. 保存 Markdown 文件到输出目录，并报告文件路径和检查结果。

## 校验与门槛

判定完成前逐项检查：

- [ ] 页面清单覆盖输入材料中所有明确页面，遗漏页面有说明。
- [ ] 每个页面都有页面类型、用途说明和入口路径；入口未知时写"未在材料中提供"。
- [ ] 布局结构能让设计师判断 header、sidebar、main、footer 或主要区块关系。
- [ ] 表单、列表、详情区字段均有字段名称、字段类型、是否必填和备注；无法判断时写"未在材料中提供"，不编造。
- [ ] 主要操作、触发方式、结果说明和关键业务流程已列出。
- [ ] 弹窗、抽屉、确认对话框、成功/失败、空状态、加载和错误提示按材料覆盖。
- [ ] 输出语言为中文，格式为 Markdown，不绑定特定 UI 库。

## 失败与回退

- 输入材料不可读：列出尝试读取的路径或来源，标记 `blocked`，说明恢复条件。
- 页面清单无法判断：只问当前最关键的范围问题；不得先生成虚构页面。
- 前端代码依赖跨文件信息：优先查找同目录组件、路由、schema、columns、mock 或类型文件；找不到时在文档中标为"未在材料中提供"。
- 文档已生成但检查点无法全部验证：标记 `not_verified`，列出未验证项和原因。

## 提问契约

页面清单确认是本 skill 的阶段门槛。只有当页面范围无法从材料可靠推出，或错误页面清单会导致整份文档重写时才向用户提问；一次只问页面范围或优先级中最关键的一项。

## 证据与完成定义

最终回复必须列出生成或更新的 Markdown 文件路径，并说明依据来自哪些输入文件或用户提供材料。若某些字段、交互或提示文案不是材料明示内容，必须在文档中标注为"推断"或"未在材料中提供"。

## 边界声明

本 skill **不做**：

- 不生成 HTML、图片、Figma、Axure 或可交互原型。
- 不实现前端代码，不修改业务逻辑。
- 不绑定特定 UI 组件库；只做通用 UI 规格描述。
- 不把缺失的业务字段、权限规则或提示文案伪装成材料事实。
- 不替产品或设计师做最终视觉风格决策，只提供必要的设计建议。
