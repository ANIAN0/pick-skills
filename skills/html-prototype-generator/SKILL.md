# HTML 原型生成

把已经足够明确的界面需求制作成可直接打开、操作和评审的 HTML 原型，用真实页面行为帮助用户确认界面结构和关键流程。

## 核心原则

- 原型服务于理解和评审，不把它当作生产前端代码，也不为了展示技术能力增加无关功能。
- 可以直接使用用户描述、业务需求、UI 需求文档、现有页面、前端代码或截图。缺少正式 UI 需求文档不阻止工作。
- 优先延续当前项目已有的页面结构、视觉规范、组件习惯和交互方式；用户明确要求复刻时，以被复刻对象为准。
- 没有项目视觉依据时再选择适合当前场景的表达方式。仓库内置 KT Admin 资产只是后台管理页面的可选默认模板，不是所有原型的强制外壳。
- 只询问会导致页面范围、主要流程或界面结果明显不同的问题。能从输入和项目中确认的内容自行查清。
- 原型中的模拟数据和交互必须能够表达业务语义，不把空壳页面、不可点击按钮或说明文字当成功能替代品。
- 审查问题只用于检验原型，不会自动形成新需求。修改原型前把问题追溯到直接输入或项目事实；输入没有约束且不影响关键任务的内容，由原型制作者合理设计，不把评审者的偏好冒充用户要求。

## 输入与关联

先确认本次原型直接依据哪些用户描述、文档、页面、代码或截图。已有 UI 需求正文时优先直接链接；没有时使用实际存在的其他输入，不补写形式性文档。

同一事项沿用稳定的中文工作名称。多个输入都要明确列出，用户直接指定的链接或路径优先；不要靠文件名相似度猜测需求、设计或原型之间的关系。

## 视觉与实现依据

按以下顺序选择原型的视觉和交互依据，前一项已经足够时不再用后一项覆盖：

1. 用户明确指定的设计、品牌或目标界面。
2. 当前项目已有页面、样式、组件和交互约定。
3. UI 需求正文中已经确认的设计约束。
4. 与当前产品一致的截图或参考页面。
5. 本 skill 自带的 KT Admin 默认模板。

只有选择第五项时，才按需读取 [references/slot-spec.md](references/slot-spec.md)、[references/style-rules.md](references/style-rules.md) 和 [docs/design-guide.md](docs/design-guide.md)。可复用 `assets/` 中的骨架、片段和样式。不得修改 skill 自带的源资产；需要扩展时复制到原型输出中修改。现有片段无法准确表达需求时，直接为当前原型补充结构，不得为了服从片段库而损害需求表达。

## 制作原型

根据输入识别需要表达的页面和关键用户任务。范围已经清楚时直接制作；只有错误假设会造成大幅返工时才先询问最关键的问题。

为页面实现足以完成关键任务的结构和交互，包括真正需要的导航、表单、筛选、列表、详情、弹窗、状态变化和反馈。使用语义合理的模拟数据替代真实接口；不收集真实敏感信息，不调用会改变外部状态的服务。

修改或复刻现有页面时，先读取与页面直接相关的组件、样式、路由、schema、类型和子组件。明确要求 1:1 复刻时保持布局和行为一致；只要求表达新功能时，聚焦受影响区域，不强制增加独立的还原确认阶段。

输出路径优先遵循用户或项目约定；否则写入 `workplace/<版本>/prototypes/<工作名称>/`，以 `index.html` 作为主要入口。多页面时采用容易理解的中文页面名，并从入口页相互访问。更新同一事项时保留稳定入口，不用日期和版本后缀无限复制文件；覆盖或删除用户已有且归属不明的内容前先确认。

## 自测与审查

完成静态实现后，主 agent 必须在浏览器中实际打开原型，按主要用户任务操作，检查页面加载、导航、表单、弹窗、状态变化、反馈、关键尺寸以及控制台错误。静态阅读 HTML 不能代替浏览器自测；浏览器不可用或关键行为无法验证时如实说明，不能宣称原型已经验收通过。

主 agent 自测通过后，再使用两个新的 subagent 独立检查需求是否被原型正确表达：

1. 只向第一个 subagent 提供原型的直接输入和可打开的原型，不提供主 agent 的实现说明或预期答案。让它通过浏览器实际操作，以评审者视角提出至少 10 个有价值、能够检验页面和交互是否符合输入的问题；不得用同义问题或无关视觉偏好凑数。
2. 只向第二个 subagent 提供相同输入、原型和第一名提出的问题。让它通过浏览器逐题验证并回答，无法从输入或原型判断时明确写“不确定”，不能根据源码意图替代实际页面行为。
3. 主 agent 根据完整输入和自己的浏览器自测独立回答问题，再与第二个 subagent 的结果比较。存在会影响页面范围、信息表达、主要任务、关键交互或结果反馈的差异时，修改原型并重新自测和审查。
4. 不为了统一主观视觉偏好或输入没有约束的细节反复修改。subagent 审查不能代替主 agent 的实际浏览器自测。

需要保留审查过程时，在原型工作目录中使用中文 Markdown 文件记录；不要把审查问答嵌入页面或伪装成产品内容。

## 边界

- 不要求先执行 `ui-requirements-doc`、`project-requirements` 或其他前置 skill。
- 不实现生产前端工程、真实 API、数据库、权限系统或部署流程。
- 不把内置 KT Admin 配色、Ant Design 类名或固定片段强加给其他项目。
- 不用固定页面类型、状态机、文件日期版本或强制确认阶段代替对当前原型的判断。
- 不以“HTML 已生成”作为完成标准；原型必须能够打开，并实际表达输入中的关键页面和操作。
